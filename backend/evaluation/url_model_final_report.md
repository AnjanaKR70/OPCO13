# SCAMundo URL Phishing Model — Complete Redesign Final Report

**Date**: 2026-09-22  
**Version**: v2 (Context-Aware Feature Extraction)  
**Status**: **NEEDS FURTHER DATA IMPROVEMENT**

---

## 1. Executive Summary

The entire URL phishing detection pipeline was redesigned and retrained from scratch to address critical problems identified in the previous audit. The feature extractor was redesigned to be context-aware (brand names no longer automatically trigger phishing signals), the dataset was deduplicated, a domain-aware train/val/test split was implemented with **zero domain leakage**, and 5 candidate models were trained and evaluated.

**Key outcomes:**
- The feature extraction bias (brand keywords) has been **fixed**.
- URLs with query parameters (e.g., `google.com/search?q=hello`) are now **correctly classified as safe**.
- Dataset leakage has been **eliminated** (0 shared domains across splits).
- All 12/12 phishing test URLs are **correctly detected**.
- However, 11/15 legitimate robustness test URLs are still misclassified as phishing due to a fundamental dataset limitation — the PhiUSIIL legitimate class contains almost exclusively bare domain names without paths, subdomains, or complex URL structures.

> [!CAUTION]
> The model achieves excellent metrics on the PhiUSIIL test set (F1=0.998 on unseen domains), but still fails on real-world legitimate URLs that have complex structures not represented in the dataset.

## 4. Feature Extractor Redesign

**File modified**: `backend/feature_extraction/url_feature_extractor.py`

| Change | Before (v1) | After (v2) |
|---|---|---|
| `PHISHING_KEYWORDS` | Mixed action + brand keywords (login, google, apple, etc.) | Split into `ACTION_KEYWORDS` (login, verify, etc.) and `BRAND_NAMES` (google, apple, etc.) |
| `suspicious_keyword_count` | Counted ALL keywords including brand names | Counts only `ACTION_KEYWORDS` — brands excluded |
| `brand_impersonation` | Brand in subdomain but not registered domain | Context-aware: brand anywhere in URL + registered domain NOT in brand's legitimate domain set |
| `BRAND_LEGITIMATE_DOMAINS` | Not present | New lookup table mapping brand names to their legitimate domains |
| Feature count | 50 | **50** (unchanged) |
| Feature names/order | — | **Identical** (backward compatible) |

## 13. Limitations

1. **Dataset representativeness**: The PhiUSIIL legitimate class contains only bare domain names. Real-world legitimate URLs with paths, subdomains, and complex structures are not represented. This is the primary remaining limitation.
2. **Synthetic augmentation scope**: Only query parameters were added to existing domains. The augmentation did not add new legitimate domains (e.g., google.com, apple.com are not in the training data).
3. **Calibration**: The model's probability outputs are not calibrated (ECE=0.16). Raw `predict_proba` values should not be interpreted as true probabilities.
4. **No real additional legitimate data**: The `Benign.zip` file in the datasets directory contains file samples, not URL data.

---

## 14. Recommended Next Steps

1. **Obtain a diverse legitimate URL dataset** containing real-world URLs from major sites (Google, Wikipedia, Amazon, StackOverflow, etc.) with paths, query parameters, and subdomains. This is the **most impactful** improvement possible.
2. **Merge the Tranco Top-1M list** (or similar domain popularity list) as a supplemental legitimate dataset to ensure the model has seen common legitimate domains.
3. **Apply probability calibration** (e.g., `CalibratedClassifierCV` with isotonic regression) using the validation set.
4. After augmenting with real data, retrain and re-evaluate before replacing the production model.

---

## 15. Decision Status

### **NEEDS FURTHER DATA IMPROVEMENT**

The model correctly generalizes across unseen domains within the PhiUSIIL distribution (F1=0.998, 0 leakage), and the feature extractor redesign successfully fixes the brand-keyword bias. However, the legitimate URL class in the training data is too simplistic to correctly classify real-world URLs with paths and complex structures. **A diverse legitimate URL dataset is required before production deployment.**
